You will coordinate a 3-round competitive review of this codebase using 5 independent AI agents specialized in Product Engineering, Software Architecture, Code Quality, Developer Experience, and Technical Strategy.

## Objective

Determine the highest-value concrete next steps for improving this codebase.

The final deliverable must be a concise, one-page recommendation. I will judge only that final recommendation, so every conclusion must be grounded in concrete evidence gathered from the codebase.

You may perform or request any deeper analysis required to support the recommendation, including:

- repository structure analysis
- architecture mapping
- dependency analysis
- code-quality metrics
- test and coverage analysis
- API/interface analysis
- security review
- performance risks
- technical-debt identification
- product/domain alignment
- maintainability and operability
- CI/CD and developer workflow
- documentation quality
- duplicated or unnecessary complexity

Do not recommend changes merely because they represent industry best practices. Every recommendation must answer:

1. What evidence in this codebase justifies it?
2. What problem does it solve?
3. What happens if we do nothing?
4. What concrete change should be made?
5. What expected benefit will result?
6. What is its estimated effort/risk?
7. Why should it be prioritized over competing improvements?

## Five Independent Agents

Each agent must independently produce a different improvement thesis.

Avoid premature consensus or five variations of the same recommendation.

Encourage disagreement where evidence permits it.

## Round 1 — Independent Diagnosis

Each agent inspects the available evidence and proposes its highest-value next steps.

For every proposal require:

Evidence → Diagnosis → Recommendation → Expected Impact → Effort → Risk

Review all five proposals critically.

Identify:
- unsupported assumptions
- missing evidence
- weak causal reasoning
- low-value recommendations
- duplicated proposals
- important areas overlooked

Provide explicit feedback to every agent.

## Round 2 — Evidence and Challenge

Agents revise their proposals based on the feedback and gather additional evidence where necessary.

Require agents to challenge one another's major assumptions and priorities.

Distinguish clearly between:

- verified facts
- measurements
- architectural inference
- hypotheses
- subjective engineering preference

Reject recommendations that cannot be sufficiently supported.

Perform another review and provide candidate-specific feedback.

## Round 3 — Final Recommendation

Each agent produces a final candidate describing what should concretely happen next.

Recommendations must be actionable enough that an engineering team could begin executing them immediately.

Prioritize actions rather than observations.

## Final Output

Present all 5 candidates, but keep each concise.

For each candidate include:

- Core thesis
- Top 3–5 actions
- Evidence supporting them
- Expected impact
- Estimated effort
- Main risk/trade-off
- Why these actions should happen now

Score each candidate from 0–100 on:

- Evidence quality
- Expected impact
- Actionability
- Prioritization quality
- Architectural soundness
- Product relevance
- Cost/benefit
- Risk awareness

Then produce a final one-page recommendation containing:

### What I recommend
The 3–5 concrete actions that should happen next.

### Why
The strongest evidence supporting those actions.

### Priority
What should happen first, second, third, etc.

### Expected outcome
What materially improves if these actions are completed.

### Do not do yet
Important improvements that are valid but should deliberately be postponed.

Do not merge recommendations merely to create consensus.

Choose the strongest position supported by the evidence.

The final recommendation must be opinionated, specific, executable, and traceable to concrete facts about this codebase.
