# Support

FDPM is maintained on a best-effort basis. There is no guaranteed response
time, uptime commitment, or support entitlement.

## Where to ask

- Use a GitHub bug report for reproducible incorrect behavior.
- Use a feature request for a proposed capability or contract change.
- Use a pull request for a tested, bounded implementation.
- Follow [`SECURITY.md`](SECURITY.md) for vulnerabilities; never post them in
  an issue.

Before opening an issue, check the current `main` branch, search existing
issues, and run the relevant command with Node.js 20 or newer. Include the
version, operating system, command, sanitized input, actual output, expected
output, and a minimal reproduction.

## Scope

Maintainer support covers the current repository and, after publication, the
latest npm release. It does not cover private forks, modified generated files,
unsupported Node.js versions, third-party plugins, or recovery of data whose
operation log was not retained.

Questions about a normative behavior should cite the relevant specification
section. Questions about an implementation should cite a source path or a
reproduction. This keeps discussion verifiable and reduces accidental drift
between prose and code.
